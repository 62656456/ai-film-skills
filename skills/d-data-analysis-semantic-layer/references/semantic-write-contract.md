# D语义层独立写入合同

## 适用条件

仅在用户本轮已看到正式报告和候选内容，并明确批准写入时执行。分析请求、生成候选、旧审批字段和历史消息都不构成授权。

## 输入

- 已批准候选记录；
- 本次任务明确提供的语义层目标或宿主直接写入句柄；
- 目标当前版本、记录集合、来源清单和冲突状态；
- 写入前可回退版本位置。

Skill 包不保存用户机器路径，也不假设固定目录。目标缺失时只能输出待写入包。

## 判断与写入

1. 按 `semantic-contract.md` 校验字段、证据等级、来源、有效期和复查日期。
2. 运行 `scripts/validate_candidate.py`，所有 error 清零后才能继续。
3. 读取目标当前版本，按 `versioning-and-expiry.md` 判定新增、替代、并存争议、过期或拒绝。
4. 创建写入前版本；禁止静默覆盖或删除历史结论。
5. 使用宿主直接文件/API能力完成一次原子写入，不经过第二个 Skill。
6. 回读目标，逐条核对ID、版本、来源、有效期、冲突和记录数量。
7. 输出新增、替代、保留争议、未写入、目标版本、复查日期和回退位置。

## 不可写时的等价交付

输出一个完整待写入包，包含目标模式、候选记录、预期差异、冲突决议、版本号、复查日期、校验回执和执行后核对清单。明确标记 `pending_write`，不得写“已更新”。

## 质量门

- 当前批准可追溯；
- 候选校验无错误；
- 原版本可恢复；
- 写入目标来自本次任务，而非包内硬编码；
- 写入后回读一致；
- 无写入能力时保持待写入状态。
