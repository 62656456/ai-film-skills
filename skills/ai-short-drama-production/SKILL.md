# AI 短剧生产编排

把创意编排为可追溯的生产任务：导演判断、资产与空间/动作合同 → 五列人读分镜 → 六模块视频母提示词（数字10为内部信息覆盖）→ 实际画面 QC。按用户本次交付范围进入对应阶段，不要求每次从头走完整条流程。

这是**控制合同层**，不重写既有导演或资产方法：

- 剧本解读、视觉概念、节拍/镜头归并、台词时序、剪辑动机与可生成性，按 `references/independent-production-core.md` 在本包内完成。
- 人物、场景、道具的真实外观、状态与审核，按本包内置资产合同完成。
- 类型色彩、镜头偏好与材质参数，按本包内置类型适配表完成。

本 Skill 把这些决定变成本包内可传递、检查和回写的控制合同。用户只要控制合同、分镜表或局部修改时，停在点名范围；进入分镜/提示词交付时读取本包 [production-handoff.md](references/production-handoff.md)。该文件自带与5.6日常结构对齐的最小交付合同，不要求读取或安装其他 Skill。

## 1. 先判断输入，补齐缺口

从用户输入提取：受众/时长、剧本形态、人物目标与阻力、场景、主类型、目标平台、已有关联资产或草图。缺失项写为 `pending`，不可用空泛的“爆款”“电影感”代填。大纲、草图或口述造成的补充事实必须写 `assumed`，不可伪装为原始设定。

| 输入状态 | 首要产物 | 本包处理层 |
|---|---|---|
| 只有故事点子 | `narrative_beat_contract` | 导演与剧本层 |
| 角色/场景尚未固定 | Cxx/Sxx/Pxx 资产合同 | 本包资产层 |
| 已有资产，画面易漂移 | `blocking_map` | 本包镜头层 |
| 已有草图或分镜草稿 | `sketch_to_shot_brief` | 镜头与提示词层 |
| 对打、追逐、抢夺 | `action_ledger` | 镜头、提示词与成片检查层 |
| 画面“平”“假”“不高级” | `lighting_plan` | 镜头、提示词与成片检查层 |

## 2. 按交付范围编排生产

1. 先按本包内置导演判断完成剧本三层读法、视觉概念与场策略；再从其判断结果写可检验的开场钩子、目标/阻力、策略或权力转折、结尾钩子。
2. 按本包内置资产合同登记 Cxx/Sxx/Pxx；已有用户锁定的资产直接沿用，未锁定部分可作为明确标记的候选支持文本分镜与提示词。正式生成前须完成相应资产审阅，不以视频抽卡替代资产库，也不以尚无参考图为由拒交用户点名的文本方案。
3. 对镜头建立 `blocking_map`：先固定世界方向、空间锚点、人物位置/朝向/高度、道具与光源，再按每个机位推导画面左右、前后、遮挡与出框。平面图只在足以表达当前空间时使用；摄影机移动或切镜本身不改变世界状态。
4. 用本包类型适配层提供镜头、色彩和材质参数；类型参数不得改变审核过的资产外观。
5. 仅在需要时叠加下列专项合同：草图转镜头、布光、动作。详细字段见 [control-contracts.md](references/control-contracts.md)。
6. 先形成五列人读分镜；用户指定一个总时长时，再把已选方案编译成一条覆盖全部时长的完整视频母提示词，六模块只出现一次，不拆成六条提示词。一个总时长生成片段可包含多个明确切点的镜头；用户锁定连续长镜时不得插入切镜。固定、单项或复合运镜按观看目的选择，并写明具体起止、路径、朝向、速度和接力。节拍密度由动作、台词与辨认时间决定，不固定动作数或镜头数；无法兼容用户锁定条件时先指出具体冲突，不能擅自拆镜、改时长或省略结果。
7. 本包成片检查层用实际画面复核，不以平台任务成功、漂亮单帧或重复生成当作通过。

## 3. 六种可控性合同

### 3.1 剧本节拍合同

写 `hook / want / obstacle / strategy_shift / power_turn / cost / cliffhanger`，并记录观众信息差、人物进出状态差、情绪曲线与视觉概念引用。每项必须是画面或台词可观察的事实。不要把“反转很强”当作内容。

### 3.2 资产库合同

资产库（`asset_registry`）是已批准 Cxx/Sxx/Pxx 的索引，不是图片文件夹。每个条目至少有：`asset_id`、版本、状态、参考图、锁定特征、可变状态、来源镜头、最后审阅日期。版本变化使用后缀（如 `C01b`），绝不覆盖已批准版本。

### 3.3 场面调度图

每张图固定：画面朝向、左中右/前中后空间锚、A/B 的位置和面向、道具初末位置、行动路径、进出画、遮挡物、摄影机位置/镜头方向、180°轴及权力几何。发生移动时，用编号阶段 `T0 → T1 → T2`，而不是把整段动作写成一句话。调度先于机位：先让走位和物件关系承担变化，再选择摄影机如何观察。

### 3.4 布光图

每镜列出实际采用的主光及必要补光、轮廓/背景光的世界位置、方向、色温、强度或光比及照亮区域，光源可在画内或画外；记录开镜/尾帧连续性，不为填满表格凭空增加灯光。资产图用可读性优先的标准光；剧情镜用叙事光，但不可让无来源泛光、死黑或滤镜替代布光。光色服务已经确定的视点、空间权力和信息显露顺序，不反过来取代它们。

### 3.5 动作账本

打戏先拆为可生成的交换单元：`起势 → 位移 → 接触/落空 → 反应 → 定格尾帧`。每个单元写清发力主体、清晰起点/路径/终点和受力反应；武器、手脚与镜头方向同时写进正向和负向约束。动作密度由“因果环节数 × 持续时间 × 人物数量 × 镜头运动”判断；只在相应镜头结构未锁定、剧情信息与结果保持时拆镜或采用画外暗示。若密度与用户已锁定的结构、时长或必须可见的动作冲突，指出具体尚未解决的约束，不擅改镜数、台词或动作呈现。

### 3.6 草图转镜头

草图只锁构图和关系，不直接锁人物脸、服装纹理或成片风格。先标记可继承元素（构图、地平线、机位、人物占比、视线、主光方向）与必须由本包资产和类型适配层补齐的元素，再生成关键帧。

## 4. 五列分镜与六模块装配

正式交付采用本包 [production-handoff.md](references/production-handoff.md)：默认五列人读分镜与一条完整六模块母提示词（同一总时长内六模块只出现一次）；数字10是内部覆盖项，不是十个外显标题。用户明确锁定的合法表格格式、镜头结构、顺序、时长、台词及摄影决定优先；只交指定层，不因适配默认包装改写用户结构。

六类内部合同按以下关系编译，用户可见正文使用人物、地点与道具的自然名称，不输出内部编号、路径、哈希或审核标签：

- 节拍合同进入情绪目标与分段脚本，保留人物目的、信息差、动作改变和原台词。
- 资产、调度与草图合同进入主要主体、场景状态及分段脚本，固定世界位置，再按镜头重算画面投影。
- 动作账本进入分段脚本，写明起点、路径、接触/落空、反应和终点。
- 摄影方案进入视觉风格与分段标题/正文；不在格式化时把已选复合路径缩成“缓推”或“跟随”，也不擅自增加运镜。
- 布光合同进入场景状态、视觉风格与每镜受光描述，保留同一世界光源。
- 尾态与针对性负向进入分段脚本及全段硬约束，检查人数、资产、换手、轴线、光源和环境连续性。

## 5. 生成前门禁与回炉

按当前交付阶段检查：`ready_for_prompt` 只表示文本方案与交付结构自洽；`ready_for_generation` 还要求相应资产已审阅、真实平台限制和执行条件已核实。未审资产不得被记为已通过，但不阻断候选文本交付。

- [ ] 叙事钩子、目标、阻力与结尾钩子可观察
- [ ] 剧本补充事实均标记 `assumed`，视觉概念、信息差、权力转折和观众情绪已有导演判断依据
- [ ] 内部资产引用一致，候选与已批准状态区分；正式生成所需资产已完成人工审阅
- [ ] 调度图能解释人物、道具、摄影机与 180°轴
- [ ] 布光的画内/画外来源与世界方向可解释，且没有遮蔽关键叙事信息
- [ ] 动作账本的每一步有起点、路径、终点与反应
- [ ] 草图只继承允许字段；人物外观仍引用批准资产
- [ ] 用户锁定结构未变；每个切点或连续镜头均明确，总时间连续、台词完整、跨镜尾态可接
- [ ] 默认五列分镜与六模块正文均为实际完整内容；数字10已覆盖，内部编号/治理字段未漏入提示词
- [ ] 只读最终提示词可以还原已选摄影方案、动作过程与结果，没有靠标题/字段计数代替语义核对

失败时在本包内按归属回炉：故事/视觉概念/节拍/台词回导演与剧本层，资产漂移回资产合同层，空间/轴线/动作回镜头层，字段错误回提示词编译层，实际画面不符回成片检查层。禁止只靠“再生成一次”绕过问题。
