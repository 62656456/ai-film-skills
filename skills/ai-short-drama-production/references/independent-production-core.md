# AI短剧独立生产核心

本文件把剧本、资产、类型、分镜和质检能力按一个 Skill 包的结构编写，不要求接收者安装配套 Skill。承接已有导演方案、分镜或资产合同，只补当前阶段的实际缺口；包内自包含能力不意味着要重做其他阶段已完成的决定。

## 1. 剧本与导演判断

输入：故事意图、人物、时长、平台、用户锁定事实。

判断：人物现在想要什么、阻力是什么、为何必须现在行动、哪个动作改变局面、观众何时获得关键信息、关系或权力怎样变化、结尾留下什么新问题。

输出：钩子、目标、阻力、行动策略、转折、代价、结尾钩子，以及逐场视觉概念和场策略。

质量门：每个节拍必须造成可观察的新状态；不能只用解释性台词或空洞情绪词推动剧情。

### 创意镜头与转场候选

用户要创意思路，或当前设计确有值得探索的未定位置时，给具体候选：对应哪段剧情、想让观众感到或发现什么、起始画面如何经动作/遮挡/焦点/摄影/剪辑/声音变为结束画面、怎样接回前后镜头，以及主要适用条件和代价。数量随问题而定，不让每个镜头强制出多套，也不因用户举例就把例中的道具和拍法搬入当前故事。

候选单独呈现，保留主方案和锁定事实；具体媒介按当前请求，思路默认交文字。设计可以明确可行条件和待验证项，但没有实际媒体时不得声称试拍成功。缺平台、账号、密钥或参考图不妨碍交付创意思路。

只有用户明确选中的创意及对应范围才并入后续设计，未选方案不进入主分镜、主提示词或生成队列。采用创意不自动授权生图、视频、外部模型调用，也不代表 Skill 版本通过用户验收。后续需要分镜、提示词或真实媒体时，按当时已授权的交付范围继续，不重复询问已确认的选择。

## 2. 人物、场景与道具资产

为人物建立 Cxx：外观锁、服装锁、比例、可见特征、禁止漂移项、审核状态。

为场景建立 Sxx：空间拓扑、左右/纵深、门窗与固定锚点、光源、可拍机位、禁止漂移项、审核状态。

为道具建立 Pxx：外形、材质、初始持有人与位置、变化节点、最终状态、禁止错误状态、审核状态。

资产未获人工批准时，可在明确候选边界下完成文本分镜与提示词；不能标成已批准资产，也不进入正式视频生成。用户已确认的资产与结构直接继承，不重复发明或要求无意义的再批准。

## 3. 类型适配

输入题材与场景需要，输出可观察的 `style_route`：色彩区域、色温、光比、材质、镜头倾向、动作节奏和负面约束。类型参数不得改变已经批准的人物、场景和道具外观。

## 4. 镜头与提示词

每个镜头写清职责、首态、尾态、景别、机位、焦段、摄影机行为、人物动作、道具状态、声音、台词时间窗、切点和连续性交接。镜头时间由动作、台词和观众读取决定，不机械等分。

正式交付按本包 [production-handoff.md](production-handoff.md) 分阶段执行：分镜请求用五列人读分镜或既定格式，提示词请求才用六模块母稿，两者都要时分别交付同一方案。六模块为生成任务、主要主体、场景状态、情绪目标、视觉风格、分段脚本；数字10仅作内部适用性覆盖。一个总时长不触发提示词阶段；用户锁定格式、结构、时长和台词优先。

## 5. 生成前与生成后检查

文本交付按当前范围检查剧本因果、世界空间与各镜投影、轴线、动作、台词时长、光源、尾帧、五列/六模块及用户锁定，只查本次适用项。导演决定已成立时直接承接，提示词仅编译已选分镜，不能以排版为由重新导演。进入正式生成前另外核对相应媒体授权、资产批准与实际平台执行条件；文本或创意候选通过不自动进入生成。

生成后检查故事是否看懂、人物和场景是否漂移、动作因果是否成立、声音是否贴合、是否出现字幕乱码和生成穿帮。失败时回到最早出错层，只修对应合同，不以重复抽卡代替诊断。
