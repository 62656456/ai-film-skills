# 本包内导演与编剧能力路由

本文件只路由当前包内已经按 Skill 结构编写的参考模块。

## 剧本创作与修改

适用：从零写剧本、完整改写、场景修复、对白修改、去AI味。

读取顺序：

1. `screenplay-writing-core.md`：建立可复述的完整故事、人物行动、对白目的和结局选择。
2. `screenplay-exemplar-benchmarks.md`：只在完整剧本、严肃改写或用户明确要求高质量时，用真实优秀剧本做机制校准。
3. `screenplay-state-engine.md`：在正文成形后检查因果、信息、人物策略、关系、道具和伏笔回收。
4. `anti-laziness-contract.md`：检查是否用摘要、空话、样例片段或流程代替用户要求的完整结果。

输出：用户点名的完整剧本、可直接替换的改写或明确诊断；内部卡片不得替代正文。

## 独立冷读审查

适用：需要与写作者解释隔离的剧本审查。

只读取 `screenplay-cold-read-protocol.md`、原剧本、用户锁定项和必要格式信息。输出最早断裂点、证据、影响范围和可执行修复，不读取写作过程说明。

## 导演分析与分镜前设计

适用：导演方案、场景设计、人物表演、视觉概念、声音、剪辑、时间和分镜前判断。

读取顺序：

1. `verified-director-logic.md`：导演判断的证据和因果骨架。
2. `director-thinking-spine.md`：观众终点、人物压力、场面调度、影像、表演、声音和剪辑决策。
3. `director-workbench-protocol.md`：长项目、完整场景包和分阶段覆盖。
4. `anti-laziness-contract.md`：交付完整性检查。

输出：完整 `DIRECTOR_PLAN`，包含观众终点、戏剧变化、视觉概念、表演动作、声音/剪辑/时间、世界状态、连续性和镜头制作约束。所有生成该结果的规则均位于当前包内。

## 当前事实和来源敏感内容

只有任务确实依赖现实世界的最新事实、真实导演、真实影片、历史事件或当前平台能力时，才读取 `research-update-protocol.md` 并检索公开权威来源。公开来源只用于核实事实，不成为运行依赖；无法核实时标记不确定性。

## 完成门

- 所需判断能由当前包内文件完成。
- 没有要求接收者配置本机路径或另装技能包。
- 没有把卡片、工作台、状态账或检查表当作用户点名的剧本/导演方案。
- 任何未覆盖内容明确列出，并提供可续接锚点。
