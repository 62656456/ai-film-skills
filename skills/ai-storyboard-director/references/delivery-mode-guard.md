# 正式交付模式门

## 1. 交付模式

本文件只管当次交付，不重复生产合同的空间、摄影或格式细则。开始成文前先按用户最新要求确定：

| 用户要求 | 本次直接交付 |
|---|---|
| 普通“拆分镜、做分镜、写视频提示词、继续分镜” | 五列人读分镜＋完整六模块母提示词，同轮完成 |
| 明确“只要提示词、不要分镜表” | 只交完整六模块母提示词 |
| 明确“先看分镜、只要镜头表、暂不写提示词” | 只交五列人读分镜 |
| 检查或局部修改既有成品 | 简短指出实际问题，交所要求的完整修正版；明确只要局部时只交该局部 |
| 纯打戏设计、只编排交锋，未要求分镜或提示词 | 完整可读交锋及用户要求的摄影／节奏处理；不自动追加分镜表或生成提示词 |
| 拉片、成片诊断或仅审查素材 | 先说明实际检查范围，再交有证据的观察与问题定位；只按用户要求改稿，不自动补成原片动作或启动生成 |

点名提示词时，摘要、分析、短镜头句、六个空标题、映射表或保存成功都不能代替完整正文。只有关键缺失会改变结果时才追问；普通未逐镜确认的请求依据现有剧本完成一个方案，不增加确认轮次。

用户要求总时长N秒时，一条母提示词覆盖N秒，六模块只出现一次。内部镜头、资产或剪辑单元不能自动变成多条重复提示词。用户要求或已核实硬限制需要拆分时，保留母提示词，另交各自自足的生产单元。

## 2. 成文合同

按 `references/production-contract.md` 实际写作：
- 五列分镜突出主动作、具体摄影过程、关键变化与落点，五列互相分工；不额外增加第三份长摘要。
- 六模块都有本条具体内容：任务、主体、场景、情绪、视觉风格、分段脚本。数字10是内部适用性检查，不要求每条强行写满十种正文。
- 分段标题直接显示景别、机位、主要摄影过程和落点；重要光学、速度或接力可进入标题。标题与正文共同保留全部既定摄影信息，不要求七字段填空或同一参数重复两遍。
- 正文按行动与摄影的实际先后组织；复杂运镜保留分阶段路径、触发、焦点／遮挡／声音接力与终点，不能只写“流畅跟拍”。
- 共用设定集中定义，逐镜只写当前执行所需内容；实际素材用途在对应模块说明。
- 全段硬约束尾块仅在有新增且必要的共同限制时出现；没有则省略，不为完整感编造负面清单。
- 无关角色、道具、动作、后续剧情及其否定表达不进入当前镜头；有作用的画外声、遮挡、倒影和用户明确限制不得误删。
- 正文用自然名称，不写内部编号、路径、版本、状态、回执或工程字段。

## 3. 行为验收

从实际成品检查：
1. 用户剧情、台词、人物、道具、动作结果和已定镜头是否完整对应；是否擅加镜头或新戏；
2. 能否根据最终文字还原机位、光学、取景、路径、焦点、速度、遮挡、切点和落点；关键动作是否既看得清又留够时间；
3. 空间投影、轴线、光源、环境与物理反馈是否连续；
4. 是否存在无作用的排除句、同义重复、机械填项、数值伪精确，或过度压缩造成的遗漏；
5. 双层／单层、六模块一次、总时长和可复制性是否满足当次要求。

复用这次核对修正具体问题，不再增加一套长报告。格式、字段、词数或机器扫描不能独立证明语义准确；验收报告不进入提示词正文。
