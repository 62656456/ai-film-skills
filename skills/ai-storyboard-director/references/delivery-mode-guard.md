# 交付阶段判断

仅在当前阶段确有歧义时读本表，常规请求直接按入口交付。

| 请求 | 当次成品 |
|---|---|
| 创意镜头、给些拍法思路、转场点子 | 单独或在主方案后交可比较的思路与取舍；按 `creative-shot-ideas.md`，不默认出图、试拍或编译 |
| 分镜、镜头表、拆分镜、继续分镜 | 可读镜头设计；已有格式优先，默认五列；不附生成模板 |
| 先分镜，之后做视频 | 当次只到分镜，下游用途不提前改变媒介 |
| 视频提示词、已定镜头转提示词 | 按 `production-contract.md` 编译一条六模块母稿 |
| 分镜和提示词都要 | 分别交付同一方案，转换格式不重新导演 |
| 实际生成视频 | 需要真实执行和可观看结果，文本完成不等于视频完成 |
| 明确要求出分镜图或关键帧 | 按点名范围交图；静帧不证明运镜或转场效果，不自动续做视频 |
| 局部修改或检查 | 保持现有媒介与未受影响决定，只改请求范围 |
| 纯交锋设计或拉片 | 所需设计或有证据的观察，不自动扩展成品 |

“测试技能”“看看成果”“继续”继承当前阶段及最新决定，不单凭结果、测试或创意等字样自动升级到实际生成。若上下文已经明确要成片，则继续完成该成片；现有来源确实无法判定且差异会改变结果时才澄清。用户纠正覆盖旧模板，不要求用户补说“不要提示词”才能拿到分镜。只输出所需成品，内部检查和保存记录不代替正文。

采用创意思路只更新用户点名的设计，未选思路继续独立保留；没有采用决定的内容不得混入正式镜序。设计阶段无需查询生成平台或密钥，也不以这些条件缺失阻断成品。
