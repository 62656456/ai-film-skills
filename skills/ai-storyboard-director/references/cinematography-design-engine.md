# 5.4.3 电影摄影与大胆镜头设计引擎

## 1. 作用

本文件负责让镜头设计不局限于安全的建立镜头、跟拍、弧移和拉远，而是在剧情允许时主动调用广泛的电影摄影语言。大胆不是强制复杂、强制炫技或只做不可能空间；大胆是敢于从完整工具箱中选择最有表现力的视点、光学、调度、运动、剪辑或视觉变换，并把它们写成可执行过程。

本文件与同目录的剧本理解、生产合同和交付门共同构成完整、独立的摄影设计能力。

## 2. 举例语境

用户可能举出斯皮尔伯格镜头、西西可里运镜、鱼眼镜头、推上摇镜或其他具体名称。这些默认是说明性证据，说明用户要求镜头选择更广、更主动、更有导演创造力；它们不是固定四项，不是全片风格，不是范围上限，也不会自动覆盖已经锁定的剧情、人物、空间和镜头决定。

只有用户明确说“就用这个镜头、锁定这种设计、全片统一采用”时，具体例子才升格为采用项。对含义不唯一的命名，不擅自补成另一种术语；先根据用户给出的可见效果或当前剧情设计，必要时只追问一个会改变方案的问题。

## 3. 完整镜头搜索范围

设计前按当前场景需要，从下列维度中主动搜索；不是每场都要使用全部维度。

### 3.1 镜头职责与信息顺序

- 建立、主镜头、覆盖、反应、插入、揭示、延迟揭示、主观、观察、监视、越肩、双人关系、群像调度；
- 先人物反应后奇观、先结果后原因、先局部后全貌、先遮挡后显露、把答案留在镜头终点；
- 连续长镜、切分覆盖、跳切、省略、平行、交叉、动作匹配、声音桥和节奏性断裂。

### 3.2 人物调度与摄影机关系

- 固定观察、领先、尾随、平行、对向、侧后、绕行、交叉换位、主体接力；
- 人物主动逼近、退让、让位、遮挡、显露、进入前景、退出画面或改变纵深；
- 摄影机顺应人物、拒绝跟随人物、被人物带动、提前等待、落后追赶或越过主体后反看结果。

### 3.3 景别、构图与视点

- 极远景、远景、全景、中景、近景、特写、极近特写及非阶梯式跳变；
- 高、低、贴地、顶视、仰视、倾斜地平线、窥视、第一人称、身体附着、物体视点、反射视点；
- 对称、失衡、负空间、框中框、前景压迫、深焦纵深、遮挡构图、中心穿透和边缘进入。

### 3.4 焦段与光学

- 超广角、广角、标准、长焦、超长焦、微距及焦段变化带来的透视、压缩、速度和空间关系；
- 鱼眼、分割焦点、浅景深、深焦、移焦、焦点接力、推拉变焦、变形宽银幕、镜面、折射、棱镜、柔焦、镜头呼吸和可控畸变；
- 光学选择必须改变观众对距离、体积、心理、速度或信息层次的感受，不能只写镜头名称。

### 3.5 摄影机中心位移与朝向

- 推进、后撤、横移、纵移、升降、吊臂、摇臂、轨道、环绕、螺旋、弧线、斜向、俯冲、冲顶、穿越、无人机、FPV、斯坦尼康和手持；
- pan、tilt、roll分别描述朝向变化，不能和摄影机中心位移混写；
- 推、上升、摇摄、俯仰、横移、变焦和人物调度可以组成复合镜头，但每个阶段都要有新的可见任务。

### 3.6 运动质感与速度曲线

- 完全静止、呼吸式微动、缓启、匀速、加速、减速、突停、回弹、失重、沉重手持、机械精确、漂浮、冲击和惯性延迟；
- 运动模糊、快门质感、速度坡度、时间压缩或延展只服务动作辨认和情绪压力，不掩盖人物表演与物理因果。

### 3.7 遮挡、转场与镜头内部接力

- 人体、门柱、衣摆、车辆、烟、火、暗部、反射、光斑、运动模糊和实体表面可形成遮挡或隐藏拼接；
- 动作、方向、构图、声音、颜色、形状、焦点或物件可以接力到下一镜或下一空间；
- 甩镜、匹配切、擦镜、穿门、穿窗、穿反射、前景掠过和声音先行必须有明确入口、出口和连续锚点。

### 3.8 时间、空间与AI／CG扩展

- 局部冻结、慢速、回卷、时间差、克隆、分屏、万花筒、无限缩放、尺度穿透、重力翻转、解构重组、非欧连接和环境连续变换；
- 这只是完整摄影工具箱的一部分，不是大胆镜头的默认答案；现实可拍的机位、光学、调度和剪辑同样可以非常大胆；
- 使用视觉变换时，先锁真实主体和世界锚点，再写触发、作用范围、摄影机是否受影响、阶段变化和终点后果。

## 4. 从广泛搜索到一个完成方案

内部按以下顺序组合，不向用户展示机械表格：

```text
剧情变化与观看任务
→ 人物调度和信息顺序
→ 观众视点与镜头职责
→ 景别、构图、焦段与光学
→ 摄影机中心路径和朝向
→ 焦点、遮挡、速度与运动质感
→ 剪辑／转场／视觉变换
→ 终点构图和剧情结果
```

场景需要鲜明设计时，至少形成两种结构真正不同的内部候选。一个可能依靠人物反应与延迟揭示，另一个可能依靠鱼眼主观、长焦压缩、推上摇复合运动、固定机位调度或声音桥；候选应来自不同摄影关系，不能只换名词。

最终只选择一个最适合剧情、表演、空间、节奏和生成条件的方案。简单镜头若最有力量可以胜出；大胆不等于每镜运动，也不等于忽略模型能力。

## 5. 命名必须翻译成可观察行为

用户或参考资料中的导演名、流派名、镜头名和行业俗称可以作为检索入口，但正式分镜与提示词必须展开为：

- 摄影机在哪里、相对谁、怎样移动；
- 镜头中心怎样改变朝向；
- 使用什么焦段或光学，它改变什么透视与信息；
- 人物怎样调度，何时触发镜头变化；
- 焦点、遮挡、声音或动作怎样接力；
- 观众在终点新看见或重新理解什么。

只写“某导演式镜头、鱼眼、推上摇、电影感运镜”而没有上述过程，视为未完成设计。

## 6. 输入和实现职责

- 纯文字负责剧情事实、人物目的、动作因果、镜头结构和可见过程；
- 人物／场景／道具参考图负责已批准外观和地标，不自动决定摄影机路径；
- 运镜参考视频只负责速度曲线、身体质感、遮挡节奏和运动语法，不复制人物、场景、品牌、台词、声音或完整镜头；
- 3D白模／黏土预演负责空间拓扑、尺度、站位、摄影机路径、碰撞和遮挡，不负责最终美术；
- 首尾帧／关键帧负责指定时刻构图和状态，不证明中间运动必然成立。

输入不足时可以改变实现路线或拆分生成单元，但不得凭空宣称平台支持，也不得让低优先级参考覆盖用户锁定事实。

## 7. 内部验收

1. 是否先理解剧情变化，再选择镜头，而不是先套术语？
2. 是否检查了与当前场景相关的完整摄影维度，而不是停在安全的推拉摇移？
3. 用户的具体例子是否保持说明性角色，没有变成固定清单或范围上限？
4. 所选视点、光学、调度、运动、剪辑或视觉变换是否具有可见叙事作用？
5. 命名是否已翻译为摄影机、焦段、人物、焦点、速度、遮挡和终点过程？
6. 是否存在静动、远近、速度、焦点、视点或信息顺序的有效变化，而非全程炫技？
7. 是否保持身份、空间、轴线、道具、光源、环境动力和物理连续？
8. 当前包是否已经包含本次摄影设计所需的全部运行文件？
