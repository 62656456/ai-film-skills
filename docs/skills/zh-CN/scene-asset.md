<!-- contract:purpose -->
## 1. 设计目的

用布局、出入口、固定标志、尺度、光源、材质、摄影机可达区和连续状态定义可复用场景。

<!-- contract:principles -->
## 2. 设计理念

- 先建立可审核、可版本化的资产身份，再进入分镜或视频生产。
- 平台适配可以改变语法，但不能改变已批准的 `locked_features` 和状态历史。
- 静态资产合同把身份、允许状态变化、材质、几何、布光和下游引用分开。
- 场景是可行走的世界模型，不是一张漂亮角度；反向视图必须来自同一布局。

<!-- contract:standalone -->
## 3. 适合单独使用的范围

当点名结果落在以下边界内时，可以只拿这一个模块使用：

场景参考图任务、空间锚点与反向视图计划、光影材质规则和 JSON 合同。

**单独不能声称:** 不替代剧情调度，也不能在未检查真实图片时证明场景空间一致。

<!-- contract:inputs -->
## 4. 输入

- 唯一资产编号、版本、用途、已知来源事实和仍未知字段。
- 所需视图、状态、尺度参照、目标平台和已批准参考图。
- 下游连续性所需的锁定特征、可变状态、朝向、持用关系或空间锚点。

<!-- contract:workflow -->
## 5. 流程逻辑

1. 提取必填维度，缺失事实明确标记，不臆造。
2. 锁定身份、几何、材质、物理行为、布光和状态规则。
3. 选择必要视图或状态图，编译平台适配的生成任务。
4. 执行模块质检并生成机读资产合同。
5. 失败标记为 `rework`；只有经人审的资产才能进入 `assets_approved` 和下游镜头。

<!-- contract:returns -->
## 6. 退回、重做与版本回滚

- 身份或状态缺失退回输入；几何、材质、布光或交互失败退回对应合同字段。
- 跨视图漂移退回锁定特征与主参考图，不能靠无关风格词修复。
- 审核失败保持 `rework`，结构完成不能自动晋级。

<!-- contract:review -->
## 7. 审核门

- [ ] 编号、版本、用途、必填维度、锁定特征和未知项明确。
- [ ] 比例、透视、几何、材质、接触、重量、阴影和关键面物理自洽。
- [ ] 无多余肢体、物件、文字、水印、漂移或抢主体的背景。
- [ ] 出入口、固定标志、光源、尺度、可通行路径和反向视图在同一空间模型中一致。

<!-- contract:pass -->
## 8. 过关标准与状态

- 资产任务和 JSON 合同通过模块检查，且没有未解决阻塞字段。
- `assets_approved` 必须检查真实参考图；只有文本合同仍是待审状态。

> 下方“通过”只表示本模块规定的审核门已通过；结构有效、真实任务证据和用户接受必须分开记录。

<!-- contract:outputs -->
## 9. 输出

- 主参考图任务，以及确有必要的多视图或状态图任务。
- 供分镜、提示词和质检使用的版本化 JSON 资产合同。

<!-- contract:boundaries -->
## 10. 边界、依赖与权限

- 不臆造缺失事实、不覆盖批准特征，也不把视频动作和台词写进静态资产身份。
- 没有生图工具和视觉审核时，本模块交付生成任务与合同，不能声称完成参考图。

<!-- contract:agents -->
## 11. 跨 Agent 使用

- 标准包是完整 Skill 文件夹，不是只复制一段提示词。
- `agents/openai.yaml` 只是 Codex 的可选界面元数据，不是其他宿主的运行依赖。
- 任何能读取文件夹的宿主都可输出文本合同；真实参考图还需要生图工具、文件能力和人类视觉审核。
- Agent 能阅读指令不等于原生发现或原生执行；提示词回退不能写成原生兼容。
