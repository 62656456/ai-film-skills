<!-- contract:purpose -->
## 1. Purpose

Derive original hard-science-fiction worlds, systems, organisms, equipment, interfaces, camera, and prompts from script truth, evidence, physics, production, and continuity.

<!-- contract:principles -->
## 2. Design principles

- The method stays fixed while each project's visual identity is derived from source truth, evidence, physics, production, and story legibility.
- Script fact, necessary extrapolation, proposal, approved decision, and locked decision remain distinct states.
- Research sets an evidence floor, not a creativity ceiling; high-amplitude design must expose its speculative rule and cost.

<!-- contract:standalone -->
## 3. Standalone scope

Use this module by itself when the requested result stays inside the following boundary:

Research-driven visual diagnosis, derivation, bible, directing plan, and copy-ready prompt package for a defined scene or asset.

**Cannot claim alone:** It remains Experimental and cannot claim deployment, stable practice validation, generation success, or user visual approval.

<!-- contract:inputs -->
## 4. Inputs

- Current script or scene, approved world bible, explicit premise, existing visual assets or prompts, and requested operating mode.
- Must-keep source facts, forbidden rewrites, open identity decisions, and the authority state of each existing choice.
- The requested medium and function: world, environment, interface, organism, machine, ordinary equipment, defense/rescue system, or continuity work.

<!-- contract:workflow -->
## 5. Workflow

1. Establish source authority, protect the dramatic beat, and select the applicable function contract.
2. Form research questions, open evidence, and separate fact, extrapolation, hypothesis, and unknown.
3. Derive physical boundaries, world/environment systems, candidate routes only for open decisions, and a spatial model.
4. Design bodies or systems, production route, camera, color, interface, family grammar, and continuity from function and history.
5. Build the full prompt and scene-specific exclusions, run applicable universal and conditional gates, and generate only after authority is clear.

<!-- contract:returns -->
## 6. Return, rework, and rollback

- A failed gate returns to the corresponding source, research, physics, world, system, camera, color, interface, or continuity derivation stage.
- A locked identity decision cannot be reopened by visual iteration without explicit authority; an open decision may receive genuinely different candidates.
- This experimental module has design rework but no documented version rollback manifest.

<!-- contract:review -->
## 7. Review gates

- [ ] All applicable universal gates protect source truth, dramatic legibility, evidence boundaries, originality, physical relations, production route, camera, color, interfaces, and continuity.
- [ ] Function-specific gates agree across ecology, organisms, machinery, equipment, defense/rescue systems, or interface topology only where applicable.
- [ ] Named living-artist imitation, franchise defaults, decorative technology, and actionable weapon-building detail are excluded.

<!-- contract:pass -->
## 8. Pass standard and states

- Applicable gates pass and the output states what is fact, inference, candidate, approved, locked, unknown, generated, and user-reviewed.
- Internal or generated status never upgrades this Experimental module to deployed, stable, or user-approved.

> A pass below means this module's stated gates were met. Structural validity, real-task evidence, and user acceptance remain separate states.

<!-- contract:outputs -->
## 9. Outputs

- Source and gap card, evidence-based derivation, candidate/decision record, visual or asset bible, directing plan, full prompt, exclusions, and status audit.
- For diagnosis, a concise chain from visible failure to source/physics/camera/design cause and one correction.

<!-- contract:boundaries -->
## 10. Boundaries, dependencies, and permissions

- Do not copy protected IP, imitate named living artists, provide actionable weapons construction, or generate without authorization.
- This is Experimental, not deployed; substantial research and internal checks do not equal user visual approval.

<!-- contract:agents -->
## 11. Cross-Agent use

- The canonical package is the complete Skill folder, not a copied prompt fragment.
- `agents/openai.yaml` is optional Codex UI metadata and is not a runtime dependency for other hosts.
- Text diagnosis and prompt design work in a reading host; evidence-sensitive use needs web/source access, continuity work needs files, and image generation requires an authorized media tool plus user visual review.
- An Agent may read the instructions without native Skill discovery, but prompt-only reading must not be described as native integration.
